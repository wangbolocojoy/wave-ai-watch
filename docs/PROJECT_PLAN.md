# WAVE Watch 产品与实施计划

## 1. 产品目标

为 Waveshare ESP32-S3-Touch-AMOLED-2.06 开发一套中文智能手表系统，具有可切换表盘、内置应用、统一设置中心、SD 卡音乐播放器，以及基于小智的实时语音助手。用户可以自然地说“播放 SD 卡里的周杰伦”“下一首”“暂停音乐”“把亮度调低一点”，AI 通过设备公开的动作接口操作手表并口头反馈结果。

本计划中的“控制大多数应用”限定为控制本系统内置并接入动作接口的应用。ESP32-S3 不是 Android，不能任意操作外部手机应用或执行模型生成的任意代码。

## 2. 经核对的基础与决策

- 这块板的官方资料列出 ESP32-S3、32 MB Flash、8 MB PSRAM、410×502 AMOLED、触摸、RTC、六轴 IMU、ES7210 双麦克风 ADC 和 ES8311 音频编解码器；官方仓库已有 SD 卡测试和带音频的 SD 卡视频播放器示例。[Waveshare 官方仓库](https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-2.06)
- 小智主仓库已有这块 2.06 英寸板的板型支持，包含唤醒、WebSocket/MQTT、Opus、MCP 和 OTA 等基础能力；当前主线要求 ESP-IDF 6.0.1 或更高版本。应基于小智固件扩展手表应用，而不是重新实现整套语音网络栈。[小智官方仓库](https://github.com/78/xiaozhi-esp32) · [小智支持板型](https://xiaozhi.dev/en/docs/usage/supported-boards/)
- 小智项目支持实时语音模型，但全双工需要 AEC 能力。其音频说明要求验证具体板子的采集、播放、唤醒、打断、重连和 AEC 模式；双麦克风不等同于扬声器回声参考通道。[小智音频架构](https://github.com/78/xiaozhi-esp32/blob/main/main/audio/README.md)
- 小智 WebSocket 定义了 realtime listen 模式、音频上行、TTS 下行、abort 和 MCP 消息；普通会话在 Listening→Speaking 时会停止上行麦克风。因此必须选择并验证支持持续上行和 barge-in 的实时后端路径，不能只靠 UI 显示“聆听中”。[小智 WebSocket 协议](https://github.com/78/xiaozhi-esp32/blob/main/docs/websocket.md)
- MCP 是云端调用设备能力的推荐方式。普通工具可以供 AI 调用，敏感操作可注册为 user-only 工具，不向模型默认开放。[小智 MCP 设备控制](https://github.com/78/xiaozhi-esp32/blob/main/docs/mcp-usage.md)

## 3. 总体技术路线

1. **固件底座：** Fork/固定一个可复现的小智官方版本，选择 Waveshare 2.06 board target；直接复用官方音频会话、唤醒、编码/解码、联网、MCP 和 OTA。避免先在当前 SDL 项目里重写一份 MCU 固件。
2. **系统壳层：** 在官方板级 UI 里接入 LVGL 中文表盘、启动器、应用注册表、统一导航和设置服务。当前浏览器模拟器保留为 UI 原型，不作为板上语音实现。
3. **本地动作层：** 每个应用向统一 Action Registry 注册有类型、有范围、有状态回报的动作，再映射为小智 MCP 工具。设备状态改变成功后才报告成功。
4. **音频所有权：** 语音采集、AEC、TTS 和 SD 音乐共用一套 Audio Service。不能让音乐应用和小智代码各自直接写 I2S/ES8311。
5. **配置分工：** 小智官方控制台管理账号、模型、音色和人设；手表设置管理表盘、音频、亮度和勿扰；设备设置持久化在 NVS。本机网页可通过一次性配对码同步当前支持的低风险设置。

## 4. 系统内置应用

| 应用 | 首版功能 | 可被语音控制的动作 |
|---|---|---|
| 表盘/桌面 | 三款中文表盘、左右切换、复杂功能显示、应用入口 | 查询/切换表盘，设置快捷项 |
| 小智助手 | 唤醒、实时对话、转写/字幕、音频状态、打断 | 开始对话、结束/打断、查询助手状态 |
| 音乐 | TF 音乐库、搜索、队列、播放/暂停、切歌、音量、进度 | 搜歌、播放结果、下一首/上一首、暂停/继续/停止、查询当前曲目 |
| 活动 | IMU 计步、目标进度、日汇总 | 查询步数、活动目标和当前状态 |
| 闹钟/计时器 | RTC 闹钟、倒计时、震动/提示音 | 新建、查询、取消闹钟/计时器；确认后删除 |
| 天气 | Wi-Fi 获取当前天气、温度和今日高低温；支持手动选择城市 | 查询/刷新天气；无网络时显示缓存和更新时间 |
| 秒表 | 开始、暂停、继续、归零；显示分秒和百分秒 | 开始/暂停/继续/归零、查询当前计时 |
| 计算器 | 基础四则运算、括号、清除和结果展示 | 计算范围受限的简单表达式 |
| 录音 | 开始/停止录音，保存 WAV 到 SD 卡并显示时长 | 开始/停止、查询状态；录音期间小智让出麦克风 |
| 备忘录 | 新建、查看、编辑和删除短文本，断电保留 | 新建/搜索/读取；删除须用户确认 |
| 快捷设置 | 亮度、音量、勿扰、网络、显示与省电 | 设置亮度/音量/勿扰；查询电量、网络、时间 |
| 文件与存储 | TF 卡挂载、容量、音乐扫描状态 | 查询卡状态、触发索引重建；格式化/删除保持用户确认 |
| 系统更新 | 版本、电量、升级提示 | 查询版本；重启/刷写/恢复出厂不提供 AI 自主调用 |

按当前板卡资料不把 GPS 或心率作为内置硬件能力。计步由 IMU 算法提供，并在真机测试后再标注准确性。

## 5. 全双工实时语音设计

### 真实全双工定义

- 唤醒后，手表持续采集上行声音；AI 下行播放时也不关闭麦克风。
- 用户可在 AI 说话时直接插话；检测到有效用户语音后，旧 TTS 能及时停止或压低，新语音不会被前一段播放声淹没。
- AEC、VAD/打断、网络缓冲和状态机协同工作。只支持一句一句“听完再答”的 turn-based 会话不算本项目验收通过。

### 真机前置验证门

拿到板后第一批实测必须回答：ES7210 输入如何映射到小智 AFE；ES8311 播放参考能否被 AEC 取得/软件回送；当前小智板型配置是否启用可用的 FD AEC；扬声器外放时唤醒和插话是否可靠；两麦克风对回声/噪声是否有实际帮助。若软件回声消除无法稳定工作，就优先改用耳机/近讲或降低外放场景能力，不应把它包装成已实现全双工。

### 助手状态机

`待机 → 唤醒/连接 → 聆听 → 思考/工具执行 → 播报`

全双工模式下“聆听”和“播报”并行；用户插话触发 `barge-in → 停止旧播报 → 新聆听轮次`。掉线、AEC 失效和工具失败都要有可理解的中文反馈与降级路径（按键说话/普通轮次）。

## 6. 音乐播放器与 AI 控制

### 本地播放

- 来源：板载 TF/microSD 卡；播放器能明确显示未插卡、挂载失败、扫描中和空库。
- 首版格式：MP3 与 WAV。其他格式按 ESP32-S3 CPU/PSRAM、功耗、解码器许可和连续播放测试结果决定，不预先承诺 FLAC 等高成本格式。
- 扫描目录并缓存曲目 ID、文件路径、标题、歌手、专辑、时长和播放时长；优先读 ID3 标签，无标签时退回文件名。扫描完成后，语音查找走本机音乐索引，不让模型遍历文件系统。
- UI 包含曲目列表、搜索、播放队列、当前曲目、进度、上一首/下一首、循环/随机、音量和 SD 状态。
- 音频仲裁：AI 播报优先级高于音乐；AI 开口时按用户设置暂停或 duck 音乐，播报结束后恢复原曲和进度；用户说“停止音乐”则清空/停止音乐队列但不关闭语音助手。

### 建议的音乐 MCP 工具

| 工具 | 关键输入 | 规则 |
|---|---|---|
| `watch.music.search` | `query`、可选歌手/专辑 | 返回少量候选项和稳定 `track_id`；结果不明确时先询问 |
| `watch.music.play` | `track_id` 或已确认的候选项 | 支持直接播放一首、播放列表/歌手；说明匹配结果 |
| `watch.music.pause` / `resume` / `stop` | 无 | 三者语义分开，stop 不等同于 pause |
| `watch.music.next` / `previous` | 可选队列范围 | 返回切换后的曲目信息 |
| `watch.music.get_status` | 无 | 返回状态、曲目、进度、音量和 SD 状态 |
| `watch.music.set_mode` | `repeat` / `shuffle` | 只接受枚举值 |

语音示例：“在卡里找周杰伦的歌”先展示匹配项；“播放晴天”匹配唯一时直接播，存在多首时让用户选择；“下一首”“暂停”“继续播放”是直接动作。搜不到、SD 卡移除或解码失败时如实反馈。

## 7. 应用动作安全与权限

- 给 AI 的工具按最小能力设计：操作白名单内的应用，不提供 shell、任意路径写入、任意 URL 下载或任意代码执行。
- 参数必须做类型、枚举、数值范围和运行状态检查。工具返回真实结果与错误码，UI 同步展示执行状态。
- 查询/播放/暂停等可逆低风险动作可直接做；清空音乐库、格式化 TF、删文件、恢复出厂、重启、固件更新等破坏性动作须用户在手表确认，不注册为普通 AI tool。
- 应用可在运行时声明工具列表；应用关闭或其硬件依赖不可用时，MCP 列表不暴露失效动作。

## 8. 设置与后台

- **手表设置页：** 当前支持亮度、音量、勿扰和网页配置配对；其他硬件设置按实际板载能力逐项接入。
- **天气城市：** 首版由用户手动选择城市，不依赖板上没有的 GPS；联网失败时保留上次成功数据并标注更新时间。
- **录音与语音：** 录音和小智助手共享麦克风；录音开始时暂停语音采集，结束后再恢复，避免两个功能争用音频输入。
- **小智官方控制台：** 设备绑定、模型、声音、人设及云端 MCP；固件不保存云 API 密钥。
- **本机网页配置：** 手表主动显示 60 秒一次性配对码，本机 Node 服务只代理私有 IPv4 地址；设备端仅在手表已连接 Wi-Fi 且用户主动开启配对时启动 HTTP 服务，进入 Wi-Fi 配网或断网时停止服务并撤销凭据。设备令牌仅存于服务进程内，闲置 30 分钟过期，断开时撤销。网页只可读取/更新表盘、亮度、音量和勿扰，不开放任意 MCP 执行。当前链路为局域网 HTTP，使用可信任网络；尚未加入 HTTPS。

## 9. 阶段与交付门槛

### 阶段 A：版本基线和工程结构

- 固定小智 commit、ESP-IDF 版本、分区表和本地补丁策略；复用官方 Waveshare 2.06 target。
- 保留浏览器模拟器作界面预览；确立 `AppRegistry`、设备服务接口和数据模型。
- 交付：可重复构建的基线固件、串口日志、启动/崩溃恢复说明。

### 阶段 B：板级 bring-up 和系统壳

- 真机验证 AMOLED/触摸、RTC、IMU、电量、音频 codec、TF 卡和睡眠/唤醒。
- 做中文首页、表盘切换、应用抽屉、返回导航、设置持久化和 OTA 回滚。
- 交付门槛：连续运行、触摸无失灵、断电重启配置不丢、显示休眠能恢复。

### 阶段 C：小智基础会话与 MCP

- Wi-Fi 配网、官方小智绑定、唤醒词、普通对话、播放 TTS、中文转写/字幕、断线重连。
- 注册系统状态、亮度、表盘、勿扰、计时器等设备 MCP 工具。
- 交付门槛：调用失败不会假报成功；危险动作不会被 AI 静默执行。

### 阶段 D：真全双工与插话

- 开启实时模型路径，接通 AFE/AEC；测扬声器外放下的回声、打断延迟、误唤醒、丢帧、发热和功耗。
- 交付门槛：AI 播报中用户能插话并打断旧音频；多轮运行稳定；不满足则先回退到清晰标注的普通轮次/按键说话模式。

### 阶段 E：SD 音乐与语音联动

- 挂载/扫描 TF，做曲库、解码、队列和同一 I2S 输出仲裁；实现音乐 MCP tools。
- 交付门槛：音乐连续播放、切歌/暂停、卡拔出恢复、AI 播报压低音乐、AI 播报中插话和音乐状态恢复全部真机通过。

### 阶段 F：产品化

- 功耗、震动、夜间模式、异常日志、偏好同步、OTA、中文文案和可访问性收尾。
- 交付门槛：长时间待机与连续对话测试、TF 各种文件/损坏标签测试、固件升级/回滚测试、用户配置备份/恢复。

### 阶段 G：联网与轻量应用

- 增加天气页和城市配置；断网时显示缓存与更新时间。
- 增加秒表、基础计算器、写入 SD 卡的 WAV 录音和持久化短备忘录。
- 新应用接入应用列表、统一返回导航和语音动作；录音期间由录音应用独占麦克风。
- 交付门槛：天气接口失败可理解；秒表暂停/继续准确；录音文件可在手表外播放且拔卡/空间不足时不会误报成功；备忘录重启后仍保留。

## 10. 当前项目与下一步

工作区现在包含浏览器/SDL 界面原型，以及固定在小智官方提交 `2aed8049eaf02db0377928c472d2132733b82a52` 的 ESP-IDF 固件子模块。Waveshare 2.06 板级驱动复用官方版本。目标板已加入触摸桌面、三款中文表盘、应用页、亮度/音量设置、勿扰开关、SD 音乐控制页、QMI8658 计步活动页、倒计时、每日闹钟和中文双眼语音字幕浮层，并提供系统状态、表盘、应用、活动、计时器、闹钟、音乐与设置 MCP 工具。系统状态工具可查询时间、电量、语音/AEC 状态和内置应用状态；设置 MCP 可查询和修改亮度、语音音量及勿扰模式。本机配置中心现可用手表一次性配对码连接设备，同步表盘、亮度、音量和勿扰设置。勿扰状态保存在 NVS，开启时倒计时或闹钟到期保留屏幕提醒并静音。每日闹钟设置保存在 NVS，系统时区固定为中国标准时间 UTC+8，闹钟只在固件运行时触发，不会唤醒关机或深度睡眠中的设备。语音备忘录用 SD 卡 WAV 录音并支持列表回放；天气、秒表、计算器和备忘录仍在计划中。固件使用 ESP-IDF 6.1、`zh-CN` 与 `nihaoxiaozhi` 配置完成构建，合并烧录包为 `firmware/xiaozhi-esp32/build/merged-binary.bin`。

播放器代码支持 MP3/WAV，并将 16-bit 单声道/立体声、8–48 kHz PCM 转换为设备输出采样率；目录扫描只覆盖 SD 卡根目录的 `Music` 文件夹及其内部子目录，卡上没有 `Music` 时曲库为空，不再递归整张卡；旧的 `音乐` 目录首次扫描会自动改名成 `Music`。扫描会读取 MP3 的 ID3v2.2/2.3/2.4 标题、歌手、专辑和 TLEN 时长；AI 搜索同时匹配标签、文件名及目录，曲目编号使用路径哈希，匹配多首时先返回候选项。板载音乐页显示歌手与歌名、曲库数量，列表页为整列滚动 + 懒加载（滑动时按窗口预加载，控件数量恒定）；语音 MCP 可搜索并控制完整索引曲库。进度条已接入，播放位置按解码采样累计，WAV 时长从 RIFF 数据块读取，MP3 时长优先读 TLEN、否则按可用码率估算；VBR 曲目和播放队列延迟仍需实机校准。QMI8658 计步初始化、每日步数持久化、目标设置和 MCP 查询已接入代码；倒计时和每日闹钟应用与 MCP 控制也已接入。每日闹钟依赖系统本地时间，只在固件运行期间触发，RTC 供时和休眠唤醒仍待实体板确认。触屏端文本搜索与队列编辑、热拔卡恢复尚未完成。浏览器/SDL 模拟器仍是视觉预览，和板载 UI 分开。固件已完成 ESP-IDF 编译，真机硬件和云端端到端验收仍待完成。

开发板到手后优先测 TF 引脚/挂载、MP3/WAV 播放、触摸与 AEC。真全双工及音乐/语音仲裁仍需要真机测量，不能由纯桌面模拟器验收。
